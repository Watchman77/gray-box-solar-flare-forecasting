# AIA 72-hour shared-VM experiment

The primary interface is [Notebook 09](../notebooks/09_AIA_72h_Shared_GPU_Training.ipynb). It uses fresh CNN–GRU weights, the frozen 72-hour candidate labels, 25,586 training cases from 2010–2013 and 3,905 model-selection cases from January–June 2014. The required histories reference 35,050 distinct existing image objects. No later calibration or evaluation cases enter fitting.

The [configuration](../configs/aia72_temporal_v1.json) fixes three seeds (17, 29, 43), unweighted binary cross-entropy, minimum earlier validation log loss, twenty epochs maximum and patience four. Training-prevalence log odds initialize the output bias. Preprocessing uses a reproducible sample of 1,000 distinct training images, with 1,024 pixels per image. All images remain float32 after normalization and resizing. No fitted 48-hour weights or normalization are imported.

The VM's existing raw image cache is reused. Its inventory must agree with pinned cloud generations and sizes; decoded files must match cloud MD5, embedded image identity, channel order and finite-pixel checks. The source receipt pins all requested cloud objects. Each loader worker may retain at most 96 transformed images in RAM. No large second image cache, raw-image deletion, additional disk or new VM is part of this run.

Both projects use the existing `/home/abmoses2000/.aia19b2_run.lock` with exclusive nonblocking `flock`. The lock is never unlinked or recreated. An explicit AIA release receipt, an empty GPU process list after lock acquisition, exact execution-bundle hashes and at least 20 GiB free on each disk are required before execution. The parent runner holds the common lock until the notebook kernel exits. If a process dies unexpectedly, the other project's GPU-process check must still reject a surviving kernel. Sharing files does not permit overlapping GPU jobs.

The one-time queue waits at most thirty minutes for the release. It makes no retry after failure and starts at most one notebook invocation. Each invocation allows one hour of fitting; source checks, normalization and the initial benchmark precede that interval. The six-hour cumulative fitting ceiling is a stopping limit, not an expected duration or monetary estimate. A timed-out invocation remains incomplete.

Checkpoints contain the model, AdamW state, epoch, next-case cursor, accumulated loss, earlier-selection history and Python/NumPy/PyTorch/CUDA random states. The epoch ordering has its own generator. Checkpoints are written at approximately sixty-second intervals, epoch boundaries and controlled stops. Code, data, normalization, configuration and runtime hashes must match for resumption. A mid-epoch interruption test checks identical final weights, optimizer tensors and validation histories against uninterrupted CPU fitting; it also passes in the VM environment with CUDA disabled. This is not a guarantee of equivalence between different CPU/GPU environments.

The source notebook is prepared for the shared VM. Executed notebooks, logs and checkpoints are saved in the VM bundle's `outputs/` directory and must be retrieved for review. A completed fit still requires independent best-checkpoint replay. No Cycle-25 or 2026 prediction, calibration, conformal result, fusion improvement, AR/event-disjoint result or prospective validation is claimed by this training preparation. The labels and historical input-availability limitations from Notebook 07 remain applicable.

To resume a stopped run, first inspect its saved status and coordinate a new GPU slot; then use the unchanged notebook runner with the agreed release receipt. Do not silently rerun the one-time queue, alter the training support, increase the resource limits, or refit from later-period results.
